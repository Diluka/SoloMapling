# 北斗脚本调试

在 SoloMapling 源码工作树中使用。方法、参数、返回类型和重载直接查当前源码，必要时查询匹配构建产物；说明书只维护使用流程、源码导航和适配差异。

## 按任务读取说明书

- 查询对象方法、继承、返回类型或现有脚本：读[源码导航](references/source-navigation.md)。只查资料时完成查阅即可。
- 启动、继续、关闭或恢复一次脚本调用：读[执行与收尾](references/execution.md)。
- 在脚本里执行原生命令：读[脚本命令](references/commands.md)。
- 需要打开专用角色、观察实际场景或使用直接动作：配合[游戏交互技能](../solomapling-game-interaction/SKILL.md)。

## 调试流程

1. 核对当前工作树与 `game_capabilities` 的源码身份和实际开放环境；以当前工具 schema 确认调用参数。已有会话使用其真实 `session_id` 和会话代次。
2. 定位选定环境的 `descriptor()`、原脚本及涉及的方法，确定要验证的输入、预期变化和读取证据。仅使用本次任务需要的入口。
3. 用 `script_run` 的 `kind/operation` 选择环境和操作。保存每次请求 ID、完整参数、返回的 operation 与 `context_id`。后续调用使用原上下文，查看变量或读取角色状态不重新执行原 `start`。
4. 分别判断本次调用结果、实际游戏副作用和资源收尾。单次 `SUCCEEDED` 或语言输出不能代替业务后态；`OPEN` 上下文可以用于下一次回调。
5. 超时或断连沿原 ID、完整原参数或已知 `operation_id` 恢复事实；已发生效果不重复执行。按任务需要关闭自己创建或受托收尾的精确上下文；需要后续继续时记录原 ID 和状态，再按会话所属任务处理角色收尾。

## 结果边界

- 北斗脚本启动会执行原生入口，可能打开对话、传送或改变资料。它不代表普通玩家已经通过相应点击、门户、任务或机关准入。
- 返回原生对象前，将需要的字段投影为 JSON；方法的具体类型与副作用从源码取得。
- `invocation_settled/work_settled` 描述本次调用；上下文保留、最终关闭和调度资源释放分别确认。未知状态保留为未知。
- 需要确认 Solo 适配限制时先读适配实现及切面；原生类存在的方法不自动表示当前受管环境支持。
