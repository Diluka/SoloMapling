# 运行体角色基本操作

对应 [#200](https://github.com/Diluka/SoloMapling/issues/200)，与已交付的[背包移位](inventory-move.md)共用角色、权限和结果边界。具体构建、隔离与实际部署结果以对应 Issue 的交付记录为准。

## 能力和接口

共享 Java 能力由 `soloMapling.game.action` 提供。模块使用同一 `CharacterRuntime.ModuleContext` 的作用域、控制 Grant 和唯一角色 lane；MCP 只负责身份、外部请求历史、幂等和结果投影。`RoleBinding` 管来源、实时事实与最终释放，不包含物品或战斗规则。运行体事件只记录 `NativeActionFact` 摘要，详细事实不形成第二份角色档案。

短动作复用包内 `NativeBasicActions` 的一次提交与派发机制，公开入口只接受有限类型参数，任意处理器、原始包和脚本不暴露为工具。临时包和 ThreadLocal 沿原生边界恢复释放，终态清除原生对象及输入闭包。不同角色继续使用各自通道。

所有 `game_act` 动作仍需专用会话、世界与会话代次、原请求 ID 和最近观察的 `expected_context`。每种动作的参数独立严格校验，未知字段、布尔值冒充整数及错类型拒绝。同 ID 改参数冲突；超时先查原操作和实际状态，不自动重放。

| 动作 | 参数 | 运行体基本能力 |
| --- | --- | --- |
| `move` | `direction=LEFT/RIGHT`, `duration_ms=100..3000` | 有界方向步行，不接目标坐标 |
| `stop` | `{}` | 停止当前方向移动并等实际退出 |
| `attack` | `target_oid` | 当前场景合法距离内的一次基础近战普攻 |
| `pickup` | `object_id` | 按真实地物 OID 拾取普通库存物品 |
| `drop` | `inventory_type`, `source_slot`, `quantity` | 按原生可丢弃规则丢弃指定数量 |
| `use_item` | `source_slot` | 原生单角色普通 HP/MP 恢复药剂 |
| `equip` | `source_slot`, `target_slot` | 正背包槽穿至合法装备槽 |
| `unequip` | `source_slot`, `target_slot` | 装备槽卸至正背包槽 |

普通背包类型为 `EQUIP/USE/SETUP/ETC/CASH`，正槽位 `1..127`，实际执行再核原生背包上限；丢弃数量 `1..32767`。普通装备槽白名单为 `-1..-13`、`-15..-19`、`-49/-50`，并通过原生装备元数据核实际部位，不开放现金或未知槽位。物品标志、唯一物品、满包、交易、队伍及原生限频仍由引擎裁决。

## 移动与真实停止

方向移动控制器使用当前导航提供者，其调度资源和编排工作登记在该提供者的模块作用域。定时器只负责唤醒，原生移动帧逐个作为短工作提交同一角色 lane，不在 lane 内睡眠或等待自己。父工作在全部已受理帧和定时回调真实退出后才结算，MCP 据此归还动作配额。

当前有限政策支持同一可行走 foothold 的方向步行、边缘前停止，以及普通出生点上方不超过24像素的受控落地；当前共享速度读取装备与 `SPEED` buff 属性，移动沿原 `MovePlayerHandler`；原生 `Disease.SLOW` 暂不在该有限政策内，明确拒绝并在能力公告中标示，不能按普通速度绕过减速。它不包含跨平台、攀绳、游泳、任意坠落或自主寻路。每帧重验原场景和权限，场景或代次变化停止后续输入。

#276 候选将普通与冰面方向移动接入导航共用的有效地面规则。方向输入、停止输入后的滑行、反向制动和实际停稳沿同一物理模型；`stop` 等待制动、已受理帧及定时资源实际结束。冰面穿有效防滑鞋使用普通地面规则，鞋子从实际 `EQUIPPED[-7]` 的 WZ `fs` 与实例 `SPIKES` 标记解析，普通鞋使用冰面规则。速度与跳跃仍按真实属性及适用限制读取，最高速度不因冰面额外提高。

本候选保留基本方向动作的同一 foothold、有界时长及受控出生落地边界；坐标目标和 `WALK/JUMP/DROP/CLIMB` 路线由[导航模块](../robot-runtime/navigation.md)处理。新调用读取当前装备，执行中的有效规则变化按当前规则完成本次物理收尾；具体支持及结果以实际能力公告和 #276 验收为准。

取消和 `stop` 不撤销已有位移。提前停止的 move 结果保留实际位置、时间及停止原因，不能声称走满请求时长；已有派发但已证实停止可以返回 `CANCELLED/STARTED`，同时明确 `movement_stopped=true`、`completed_duration=false`。取消 Future 或空队列本身不构成停止证明。

## 单次普通攻击

北斗原生近战包由客户端提供伤害，服务端没有可直接调用的完整客户端计算器。因此本轮使用明确命名的 `basic_melee_v1` 共享服务端政策：读取实际近战武器、原生最大基础伤害、角色命中属性及目标等级、回避与物防，计算单目标单段普通攻击。该政策不宣称与所有 v83 客户端技能、复杂伤害增强或远程武器逐项等价，支持范围在能力公告中明示。

MCP 只传目标 OID；skill固定0，距离有界。执行沿原生 `CloseRangeDamageHandler`、怪物受伤、归属、死亡、经验和掉落规则，不使用装饰机器人固定伤害模型，也不直接设怪物 HP。Solo 侧短命探针捕获本次精确角色/怪物的原生伤害进入、返回和实际扣血，避免把其他角色的 HP 变化归给本次。真实 MISS、实际伤害及击杀分别报告，派发和发攻击广播不单独构成命中。

## 物品与装备证据

拾取限定普通库存地物，不借此开放金币、NX、拾取即消费或脚本礼包。丢弃按原生规则可能生成地物，也可能正常消失，结果区分二者；仅库存减少不能证明已生成地物。装备结果提供前后装备、背包位置与总属性，包含原生冲突部位变化，不能把槽位已移但属性尚未更新当作完整成功。

药剂结果分别记录消耗数量和实际 HP/MP 效果；满血时消费不冒充正恢复。脚本、回城、全图效果等路径当前明确拒绝。跨锁读取使用原生锁顺序，避免在库存锁内等待角色 buff/属性锁。派发后部分完成或读取不完整保留已知事实并报告未知，不补发或伪造成功。

## 验收与准备

隔离使用独立数据库、网络和一致备份。所有动作分别核实际指令、结果、取消或停止及必要存档；关键背包和装备通过正常退出、同 CID 重开核验；位置只按原生实际保存的地图/入口范围检查，不承诺原地 XY 重开，不借已有 `persisted_state_verified` 扩大背包验证范围。

专用 fixture 的场景与材料可沿既有管理员接口准备，但须核精确普通角色且逐项记录，只在空闲时执行。准备发物、换图与实际 MCP 动作的证据分开；准备不代表已经完成拾取、药效、穿脱、攻击或导航。不新开任意角色 ID、发物或传送 MCP 工具。

实际服务只做已通过隔离的正常专用角色流程，保留一致备份、原玩家动态基线与具体变化归因。正式写路径不做故障注入或清空覆盖。配置、迁移、网页、端口、真实原生业务、宿主工具目录和游戏客户端玩法各自留证。
