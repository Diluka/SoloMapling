# 正常入场后的待命落地

本场景核对 #309 的正常入场落地及导航接续。记录冻结源码、JAR、环境、世界代次、
实际 scene_ref 和专用角色CID；源码、隔离与部署结果分别保存。

## 前置与采样

使用已授权隔离环境及专用角色，通过正常登录或普通门户进入已支持地图。
角色存活，原生地图ACK完成，角色仍在本次原生入场点，下方有可用真实地面；
使用正常地形及现有装备，不修改随机源、出生规则或物理参数。

1. 在正常登录或过图前开始已有 `scene_record`，随后保持待命，不调用导航或 `move`。
   每个样本最多观察10秒，最多采三个正常入场样本。核对入场原点、
   `scene-entry-fall-<CID>` 的原work、原生移动输出及实际落地后态；记录采样与基线缺口。
2. 核对本次DROP保持原横坐标、沿原生移动入口推进，最后原生位置处于实际地面，
   入场工作及其运动资源真实结算。由录像输出可核服务端发送对象与顺序，
   不能据此声称真人客户端已经收到或播放。
3. 用一个普通样本在登录后立即发起正常 `navigation.moveTo`，观察其等待本次
   入场任务真实结束后才开始路线，等待计入原调用期限。导航取消只结束本次等待；
   场景仍在时由原入场任务完成落地，不继承该导航调用的取消。
4. 正常关闭本次专用角色，核对入场carrier、短work、运动资源及场景离场真实退出。
   若本轮已经安排最小世界停启，可在该轮一并观察；不因本辅助改动追加整套训练日程。

## 判定

- 通过：本次满足前置的正常入场产生真实下落及落地，导航接续和收尾有完整证据。
- 产品失败：已满足前置仍悬停、出现水平漂移或重复运动、旧场景继续派发、资源未释放。
- 未覆盖/不确定：预算内入场点已在地面、地图/状态尚未支持、其他运动先取得会话，
  或事件缺口导致无法确认。保留实际原因，不用管理员改坐标补造正常入场。

本片不开放任意待命坠落、游泳或梯绳接管，原 MCP 有界方向动作的24px范围保持。
真人画面另行采样；没有真人样本时只结论至原生输出与原生位置后态。
