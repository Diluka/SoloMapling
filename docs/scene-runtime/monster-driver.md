# 有限怪物驱动与控制权

`MonsterSceneModule` 使用 `training_ground_jump_aggro_v2`，为100101、120100、130101、1210100提供有限的普通地面策略：沿相连foothold漫游、停驻与转向，1210100可起跳并按真实地面穿越落地。成员装载后自动运行，和狩猎、交战调用的期限分别独立；首批没有 `attackN/skillN`，身体接触由角色常驻受击入口处理。

四种均为被动身体接触怪，无仇恨时不主动选择角色。追击读取原生DPS仇恨排名，仅在同一连通地面内朝有效目标水平接近，进入8px范围制动；目标离场、死亡或失去有效仇恨后恢复漫游。冰面、水下、飞行、SPEED/Doom、主动攻击/技能、跨平台追击和复杂墙体跳越仍不支持。没有可执行驱动的headless来源不会取得controller，真人原生路径继续处理。

匹配V17的正常客户端样本见[四怪样本](monster-client-samples.md)。源码支持、候选实际验收和部署身份分别留证；本策略不声称官方客户端AI等价。

## 可追溯算法

参考 [ryantpayton/MapleStory-Client](https://github.com/ryantpayton/MapleStory-Client)，提交 `cbb0fe27cf9683a12eca0a569121d8033cdc2a4d`：

- `Gameplay/MapleMap/Mob.cpp`：WZ `speed` 转为 `(speed + 100) * 0.001` 的水平力，待机/运动切换、受击力和计时。
- `Gameplay/MapleMap/Mob.h`：MOVE为2/3、STAND为4/5、HIT为8/9，最低位编码朝向。
- `Gameplay/Physics/Physics.cpp`：惯性除以3、摩擦0.5、坡度项0.1的地面积分及空中积分结构。
- `Gameplay/Physics/FootholdTree.cpp`：相连地面、真实链端和下降穿面落地。
- `Constants.h`：物理步长8ms。

这是自制兼容客户端，README声明兼容v83服务端，当前开发资源版本与北斗并不相同。其源代码采用AGPL-3.0-or-later，本仓库按AGPL-3.0组合，版权与来源见 `NOTICE`。这里没有将角色的125px/s速度直接套给怪物。

每96ms提交一个原角色lane短命令，内部进行12步8ms预测。地面终速按V17样本校准为 `125*(100+WZ speed)/100` px/s，四种分别为62.5、87.5、62.5、125；猪起跳为-555px/s，重力为2000px/s²。地面加减速、受击后退和动作决策仍沿参考策略；起跳采用动作决策时25%概率，真实样本不认证此概率或固定节拍。

二维亚像素余量、速度和当前地面只属于临时运动上下文；每次读取原生坐标，外部变化或controller交接后复位预测。地面按原生prev/next和共同端点组成平台，链端转向；腾空允许越过起跳平台边界，下降时查真实穿越地面。原生怪物继续拥有实际位置、HP、Buff、死亡及掉落。

## 输入与控制权

`MonsterControlCoordinator` 统一候选、直接切换、仇恨切换和输入资格。正常真人优先；headless必须有当前成员、活动scope、运行中的场景驱动和对应行为支持。原锁内先验下一驱动者，再移除原controller。合法机器人攻击保留真人控制权及原生仇恨事实，撤销驱动或离场后精确解除旧句柄。

`NativeMonsterMovementActions` 在该controller的原lane内构造有限 `MoveLifeHandler` 输入。起跳帧先写cmd1初速度，再写cmd0末位置和二维速度；腾空cmd0的foothold为0，落地后恢复实际地面ID。原生处理器验证controller、更新位置、返回控制响应并广播。坐标线上有2px偏移，实际结果从原生对象回读。没有任意封包/任意怪物操作的外部接口。原生已结算伤害的回调只准备后续受击动作输入，不重算伤害或广播伤害。

角色仍处于原生 `isChangingMaps()` 状态时，场景驱动任务保持等待，`canDrive` 不授予有效怪物驱动资格，也不提交普通怪物活动输入。角色场景组件负责正常入场确认；怪物组件仅读取这一原生事实。确认完成后，同一驱动任务自动继续。

运动驱动资格与接触风险上界分别判断。首批跨段、跳跃及真人未知轨迹都按查询窗口内任意路径位置可能接触，使用原生身体伤害及角色共享2500ms节拍给出保守损失上界。该只读模型不接管controller、不移动怪物，也不将无controller的猪视为永久静止；上界可能高估实际风险，具体语义见[战术与生命预算](../robot-runtime/tactics.md#接触入伤与生命预算)。

最终派发门禁再次检查地图是否ready：明确未ready且尚未进入handler的帧返回 `mapReady=false, dispatched=false`，不计派发，也不终止驱动任务。已进入handler后的异常或未确认效果仍按失败处理，不因随后换图而自动重放。

## 证据边界与待验

原生处理器合同覆盖二维位置、起跳与末速度、运动输出、入场准入和过期controller拒绝；持续行为采用有界实际采样。候选须核四种待命活动、猪完整起落、原生仇恨追击、真人接管/退出接续、多成员和最后成员离场排空。每轮按冻结源码、场景和实际画面分别记录，未发生的随机事件保留采样缺口。
