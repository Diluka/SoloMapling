# 地图间旅行规划

`TravelPlanModule`（类型 `travel`）负责地图与门户级的路线，提供 `travel.plan`。规划返回后，控制模块持有实际执行进度，按每段出口调度当前场景导航及 `native.enterPortal`；下一段使用实际过图后的新场景。

```javascript
modules.call("travel.plan", {fromMapId: 104040000, toMapId: 100000102});
```

Java 调用同一类型化声明：

```java
context.call(TravelPlanModule.PLAN, new TravelPlanRequest(104040000, 100000102), work);
```

`fromMapId`、`toMapId` 是明确给定的非负地图 ID，因此也能为后续行程提前规划。模块可以独立装配，查询保持角色、背包及实际地图实例不变。

## 结果

| `outcome` | 语义 |
|---|---|
| `FOUND` | 找到当前支持的最少过图次数路线；已知可用的同一起终点返回空 `route`。 |
| `NO_ROUTE` | 已知端点在当前可解析的静态门户拓扑中没有连通路线。 |
| `UNSUPPORTED` | 端点不存在或版本不可用，或者可解析的连接必须经过非普通门户、门户脚本或无法确认的入口。 |

结果包含 `outcome`、`fromMapId`、`toMapId` 及有序 `route`。每段是 `TravelPlanResult.Leg`，包含：

- `fromMapId`
- `exitPortalId`、`exitPortalName`
- `toMapId`、`entryPortalName`

相邻路段的目标地图与下一段来源地图相同。一个来源地图到同一目标可以有多个门户，读取时保留各自身份；BFS 按目标地图 ID、出口 ID 固定顺序选择等价路线。`FOUND` 表达静态连接，场景内可达、当前门户状态、角色资格和实际抵达由执行结果确认。

首个业务样本的往返三段为：

| 方向 | 出口 | 目标入口 |
|---|---|---|
| `104040000` → `100000000` | `17 / east00` | `west00` |
| `100000000` → `100000100` | `23 / in00` | `out00` |
| `100000100` → `100000102` | `17 / in01` | `out01` |
| `100000102` → `100000100` | `2 / out01` | `in01` |
| `100000100` → `100000000` | `14 / out00` | `in00` |
| `100000000` → `104040000` | `20 / west00` | `east00` |

此表是原生 WZ 的验收样本，实际结果由通用搜索产生。

## 数据与执行归属

地图目录和内容使用北斗 `DataProviderFactory`、`LocalizedDataProvider`，完整目录来自原始 WZ，翻译内容按原生规则回退。地图链接沿原生 `MapFactory` 跟一层 `info/link`，链接后的门户仍属于原地图节点。门户字段复用 `PortalFactory`，版本资格复用 `MapleVersionManager`。

首期搜索普通 `pt=2`、无脚本且目标入口存在的连接。脚本和其他门户有明确静态目标时，只用于判断支持范围；未知脚本目的地、NPC交通等连接由各自规划契约覆盖。旧 `GCWorldGraph` 的出租车、登记脚本及原V1行为保持其原接口。

规划使用提供者原 scope/work 同步完成，按需读取并缓存不可变门户定义。模块配置 `timeout_ms` 默认30000、范围1～120000；取消、期限和模块停止会在下一读取/搜索检查点退出，读取中已经进入的工作需实际返回后才完成排空。元数据异常沿模块错误路径传播，与 `NO_ROUTE` 分开。

源码测试覆盖真实 WZ 六条门户、最少跳与稳定选择、平行/单向连接、同图、缺失/版本/链接/语言回退和取消排空。实际 MCP 规划、真实导航和跨图组合的验收分别记录在对应 Issue。
