# 驻点与训练地图容量冒烟

本流程接替 #327 删除的内部点数断言，观察实际训练地图准入、平台使用和占用释放。
它不要求内部点数恰好为7，也不要求角色按固定顺序巡点、每个平台必被使用或产生固定收益。
统一的版本、证据和三类结果要求见[随机行为冒烟](../maintenance/random-behavior-smoke.md)。

## 前置与预算

沿[狩猎说明](hunting.md)和项目机器人验收技能，选一个已授权的实际角色与正常训练场景。
记录源码/产物、角色来源、世界代次和精确场景引用；核对角色当前装备、能力、地图规则及
已有成员。使用现有类型和模块装配，不为冒烟添加随机源、时钟、计数器或策略替换接口。

每次观察一个实际活动，最多120秒，约每15秒采样，单段最多10次。不为了覆盖全部平台
反复搭环境。原“吞平台”问题涉及 `107000403`；仅在该地图当前可用且属于本次授权目标时
观察它，否则记录未覆盖，不复制历史44个出生点或删除地形资料制造旧结果。

## 操作与观察

1. 开始前记录实际地图成员、角色位置、已有活动/占用，以及当前容量来源。
   通过既有诊断或脚本公开读取 `SpotFinder.profileIfBuilt(mapId)` 和
   `SpotFinder.mapBotCapacity(mapId)`；profile尚未构建时如实记录WZ估算来源。
   源码入口见 [SpotFinder](../../src/main/java/soloMapling/ArtificialPlayer/BotGrindSystem/SpotFinder.java)
   与 [TrainingMapChooser](../../src/main/java/soloMapling/ArtificialPlayer/BotGrindSystem/TrainingMapChooser.java)。
   不反射改缓存或直接调用内部估算器来准备“正确答案”。
2. 通过已有 `hunting.start` 启动一段有界活动，或观察已经自然运行的训练地图选择与狩猎。
   保存实际 activity_id；材料准备、人工传送和逐阶段驱动分别记账，不算自动选择完成。
3. 采样当前方式、`activity.placement`、原生位置/成员、实际目标与导航结果，结合现有
   profile中的平台/驻点和 [BotSpotClaims](../../src/main/java/soloMapling/ArtificialPlayer/BotSpotClaims.java)
   的公开 `holders(mapId, spotId)` 核对已登记的占用。比较时保留初始其他持有者，
   核当前准入与饱和回退规则，不把估算容量误当绝不允许饱和共享的硬上限。
4. 只有自然选择并实际进入的平台才算本次覆盖；其余平台、不可达原因和样本缺口单列。
   非预期重复成员、身份错配、无法解释的超额占用或持续导航异常保留证据查因，
   不能归入随机性。随机目标、巡点顺序、击杀和掉落数不作固定通过条件。
5. 预算结束后正常停止本次活动，核同一活动回到 `IDLE`、下游动作实际退出、自己的claim
   已释放，其他持有者仍保留。若本次创建了角色，再沿正常人口/会话移除入口释放；
   不直接清占用表，不用Future已取消代替资源收尾，也不为本项新增世界停启矩阵。

## 留证

保存开始/停止请求、每次采样的时间与原始返回值、当前profile/容量来源、实际覆盖平台、
自己的claim前后态及其他成员基线。按通过、产品失败、未覆盖/不确定分别写结论；
未执行本流程时注明未验，不从删除用例或编译通过推导玩法完成。保留旧轮次原始记录，
只在相关执行链变化或新失败依据出现时重验。
